# MAWE editor scripts are inlined in this order by edit.py and the Tauri build.
# Paths are POSIX and relative to web/. Keep runtime/bootstrap modules before the
# modules that consume their exports; this file is the only build order, the
# directory layout below it is for navigation and carries no order semantics.
# editor/playback/jkl.js owns JKL playback state; editor/boot/settings-init.js
# initializes its UI at load and consumes it through the window.MaweJklPlayback facade.
# shared/gap-remove/* is the pure gap-remove core shared by MAWE and the alignment UI.
# It follows the same rule on window.MaweGapRemove: namespace.js first and
# shared/gap-remove/compat-surface.js last, which rebuilds the frozen
# window.AsrGapRemoveCore exit. Its modules read each other lazily inside function
# bodies, so their mutual order is free, but the whole block must stay before
# editor/lib/gap-remove-bridge.js, which reads the exit while loading.
# editor/lib/* publish internal symbols on window.MaweLib and read each other
# lazily inside function bodies, so their mutual order is free; only load-time
# initializers need their owner first. Within that block editor/lib/namespace.js
# must come first (it creates window.MaweLib) and editor/lib/compat-surface.js
# last (it snapshots the whole surface into the window.AsrEditorUtils compat exit).
# editor/waveform/* follows the same rule on window.MaweWaveform, with one extra
# constraint: the prototype-mixin modules install methods onto
# WaveformEditor.prototype while loading, so they must all come after
# editor/waveform/core.js (which declares the class) and before
# editor/waveform/compat-surface.js (which rebuilds window.AsrWaveform).
# editor/split/* follows the same rule on window.MaweSplit: the modules only read
# each other lazily inside function bodies, so their mutual order is free, but
# editor/split/namespace.js must come first and editor/split/compat-surface.js
# last, because that is where the frozen window.MaweSplitCore facade (including
# the pendingLinkedSplit accessor pair) gets rebuilt.
# editor/text/timed-edit/* follows the same rule on window.MaweText: namespace.js
# first, editor/text/timed-edit/compat-surface.js last, which rebuilds the frozen
# window.MaweTimedTextEdit facade.
# editor/ui/elements/* follows the same rule on window.MaweElements and must stay
# contiguous: every module runs getElementById at load time and the last one
# rebuilds the frozen window.MaweDom facade, whose 5 accessor keys keep their
# setter so external assignments still reach the owning module.
# editor/i18n/* follows the same rule on window.MaweI18n: namespace.js first (every
# module reads window.MaweI18n at load time), then the two dictionaries, the
# language state, the text rules and the DOM walker, and
# editor/i18n/compat-surface.js last. That last file rebuilds the *unfrozen*
# window.MAWE_I18N so `language` stays a live accessor, and repeats the three
# load-time statements that used to follow the export, whose order relative to the
# export decides whether startup can still read it.
# editor/boot/entry.js and the chunks after it are the load-time DOM wiring: one flat
# statement list cut into contiguous chunks, with no namespace and no facade. Assembly
# concatenates the whole manifest into a single <script>, so a chunk may only start
# between two top-level statements and the manifest order is the registration order --
# listeners on the same target fire in registration order, so these entries must stay
# contiguous and in this exact order. entry.js comes first because it declares the
# MULTI_SUBTITLE_UTILS and EDITOR_SETTINGS_UTILS consts that later chunks read directly.
