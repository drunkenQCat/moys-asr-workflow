# 编辑器模块化拆分指南

本指南把 `refactor/editor-module-split`（平铺单体拆分）与 `refactor/explode-js`
（目录结构化 + 巨型 IIFE 拆解）两个分支的方法提炼成可独立执行的步骤。读完本篇，
你应当能在不翻提交记录的情况下，从 `cf6afaa` 时代的单体 `web/editor.js` 出发，
把编辑器拆到与本分支相同的终态，并且**每一步都有可证明的行为等价性**。

配套阅读：

- [`MAWE web 目录结构化与巨型 IIFE 拆解台账.md`](MAWE%20web%20目录结构化与巨型%20IIFE%20拆解台账.md)——逐块执行记录、
  每块的三层差分数据、踩坑明细。本指南讲"怎么做与为什么"，台账记"实际做到哪"。
- [`scripts/refactor-tools/`](../../scripts/refactor-tools/README.md)——阶段一的参考实现工具。

## 1. 不可动摇的约束

动手前先接受这五条，后续所有取舍都从这里推导：

1. **产物是单文件 HTML。** `.edit.html` 必须能从磁盘双击打开。`file://` 下多文件
   ES module 被 CORS 拦死，所以无论源码怎么组织，最终产物必须是不含模块引用的
   普通脚本。ESM + 打包器被明确否决——构建工具唯一的作用是补偿它自己引入的复杂度。
2. **装配协议 = 清单顺序。** `web/editor-scripts.txt` 独占顺序；`edit.py` 与 Tauri 的
   `build.rs` 把清单逐条 `rstrip()` 后用 `\n\n` 连成**同一个** `<script>`。改动装配协议
   必须三处消费方（edit.py / server-editor / Tauri）同步。
3. **模块系统 = IIFE + 冻结命名空间。** 每个文件一个 IIFE，只向 `window` 暴露一个
   `Object.freeze` 的门面；可变状态用 `get/set` 访问器发布（`Object.freeze` 只锁
   属性描述符，setter 仍然可写）。
4. **行为等价必须可证明。** 差分测试（结构/源码/行为三层）+ 契约测试 + 失败标题
   集合比对，不用"看起来没坏"下结论。
5. **顺序是隐式契约。** 经典脚本共享全局词法作用域，加载顺序错误表现为运行时
   静默 `undefined`。顺序必须被测试守住，而不是靠人记住。

## 2. 总路线：三个阶段，先搬家后拆包

```
阶段 0  安全网与基线
阶段 1  平铺单体 → 特征模块        （editor.js 17,790 行 → 77 个平铺模块）
阶段 2  目录结构化                  （77 个平铺文件 → 按层与域的子目录树）
阶段 3  巨型 IIFE 拆解              （封装模块逐块拆到 ≤300 行级）
```

**为什么先搬家后拆包**：`git` 对纯移动能给出 100% 相似度的 rename 证据；一旦先拆
内容，"搬走了"和"改坏了"在 review 里无法区分。阶段 2 的 77 个 rename 全部以
100% 相似度落地，就是这条顺序的直接收益。

**为什么阶段 1 先拆 editor.js 而不动封装模块**：editor.js 是唯一裸奔在全局作用域的
文件（1272 个顶层声明），收益最大、边界最清晰；封装模块（utils/waveform/i18n 等）
内部已有闭包隔离，留到阶段 3 用更重的差分验证处理。

**为什么阶段 3 的 boot 接线是特例**：它是 423 条顶层语句的平铺接线，没有闭包。
正确做法是"按行连续切段 + 顺序不变 ⇒ 拼回脚本逐字节不变"，不建命名空间、不改
引用、不做差分、**也不补门面**——门面是新的风险面，而这里没有需要它解决的问题。

## 3. 通用纪律（每一批都适用，全部是用提交换来的教训）

1. **每批 = 一个提交 = 一组可验证的改动。** 批内 4-10 个簇；每批之后跑完整验证
   组合（见 §8）。浏览器回归（Playwright 全量）要么逐批跑，要么里程碑累积跑——
   我们在阶段一里连续九批没跑全量，回归悄悄累积了一百多个失败才暴露。
2. **失败比对用标题集合，不用数字。** Playwright 的 timing 类失败会随机漂移；
   在对照 worktree 上串行跑两份报告，逐条比对失败**标题集合**（脚本取标题，
   不靠眼看）。并发跑会凭空多出 timing 失败，必须串行。
3. **管道会吞退出码。** `cmd | tail` 的退出码是 tail 的。两次"带病提交"都源于此。
   先看测试输出，确认后再提交。
4. **测试要在改之前跑一次基线。** 预存失败（基线 16 个）必须先记录在案，否则
   修复后无法证明"净新增回归 = 0"。
5. **文件锁兜底。** 本工作区有外部句柄周期性锁文件（Errno 22/UNKNOWN）。所有
   写盘脚本带"失败删旧 inode 再写"的兜底。
6. **严格模式会引爆 sloppy 时代的隐式全局。** 模块 IIFE 带 `'use strict'`，原始
   单体里静默创建 window 属性的死赋值（如 `projectLoadedFromSrt = false`）会变成
   ReferenceError。拆分后用静态扫描器清一遍（见 §4.5）。

## 4. 阶段一：平铺单体 → 特征模块

### 4.1 前置：安全网

按清单逐文件断言三件事的顺序测试是这一阶段最重要的资产，它首跑就抓到 25 处
疑似违规，逼着逐条核实出真实的加载顺序约束：

- 清单内每个文件必须可解析（acorn）；
- 跨文件的顶层声明重名 → 失败（同名全局互相覆盖）；
- 跨文件的命名空间导出（`window.X =`）重名 → 失败；
- 文件在**加载期**（顶层语句、IIFE、变量初始化器）引用清单中更靠后文件的
  声明或导出 → 失败；函数体是延迟执行的，豁免。

实现约 200 行（acorn 解析 + 作用域遮蔽豁免），见 `scripts/refactor-tools/` 同期的
`tests/test_editor_script_order.mjs`。注意它看不见 `NS.xxx` 属性访问的时序——
加载时序最终仍要靠浏览器探针。

再加一个 `jsconfig.json`（`checkJs: true`，只圈 `web/`）让语言服务的引用解析
达到 rename 级精度。

### 4.2 核心 codemod 的设计

`scripts/refactor-tools/split-cluster.mjs` 是拆分的主引擎，规格是一个 JSON：

```json
{
  "file": "editor-split-core.js", "ns": "MaweSplitCore",
  "header": "模块头注释",
  "from": "pendingLinkedSplit", "to": "flashSplitFeedback",
  "exclude": ["createFloatingPanel"],
  "append": false
}
```

关键机制（全部踩过坑后固化）：

- **from/to 用符号名定位区间**，不用行号——行号随每批漂移，名字稳定。
- **引用改写用语言服务**（ts-morph 的 `findReferences`），作用域感知，rename 级
  精度。改名外部引用为 `NS.name`；簇内互引保持裸名。
- **可变状态发布为访问器对**：冻结对象上 `get x(){}`/`set x(v){}` 在 freeze 后
  仍然可写。于是外部的 `x = v` 机械改写成 `NS.x = v` 语义不变——这让改写器
  可以无脑处理所有引用，不用区分读写。
- **对象简写特判**：`{ flashHint }` 不能机械改成 `{ NS.flashHint }`，必须展开成
  `{ flashHint: NS.flashHint }`；解构模式里的简写绑定直接拒绝并人工处理。
- **append 模式**：`"append": true` 时把符号追加进既有模块（在它的导出锚点前
  插入声明、往冻结块里插导出行），用于收尾阶段的零散符号归并。
- **boot 别名改写**：模块加载期引用 editor.js 的 boot 别名（如
  `EDITOR_SETTINGS_UTILS.`）统一改写为 `window.AsrEditorUtils.`。
- **写盘兜底**：工作区可能有外部句柄锁文件，`writeFileSync` 失败就删旧 inode
  重写。

簇的划分依据：先用依赖图工具（`analyze-editor-deps-demo.mjs`）产出顶层符号的
扇入/扇出与依赖闭包，按特征前缀和耦合度分簇；低纠缠簇先行，强状态簇等状态
收拢。每批 4-10 簇。

### 4.3 每批的验证组合

```
node --check 全部改动文件
顺序断言测试（上一批的违规会在这一批暴露）
uv run python edit.py --blank 重新生成产物
node --test（JS 单测）+ Python 资产契约测试
无头探针：加载产物页，断言各命名空间挂载、零 pageerror
里程碑处：Playwright 全量 + 失败标题集合比对
```

### 4.4 e2e 测试的全局引用（最容易漏的一类）

e2e spec 通过 `page.evaluate(() => DATA.segments...)` 直接驱动页面全局。拆分后
这些符号变成 IIFE 私有，约 130 个用例会 ReferenceError——**页面本身没坏，是
测试的访问路径断了**。修复用 `fix-e2e-globals.mjs`：按模块导出表把 spec 代码里
的裸标识符 AST 级改写为 `NS.name`（跳过字符串、属性名、spec 自身的本地绑定）。
我们改了 20 个文件 408 处。这一类失败的特征是错误高度雷同
（`ReferenceError: X is not defined`），一旦见到就整类处理。

### 4.5 隐式全局泄漏扫描

原始单体在 sloppy 模式下运行，"赋值给未声明标识符"会静默创建 window 属性。
模块化后 IIFE 是严格模式，同样代码变成 ReferenceError。用静态扫描器列出所有
"赋值给本文件未声明标识符"的语句（`scan-implicit-globals.mjs`），逐条判断：
死代码删除、真状态补声明。我们全仓只挖出一处真泄漏，但它中断了整个打开工程
链路（6 个 e2e 用例失败）。

### 4.6 收尾

剩余零散符号用 append 模式并入语义所属的既有模块。终点形态：editor.js 只剩
入口职责（事件绑定、启动序列）与少量别名，顶层裸声明归零。

## 5. 阶段二：目录结构化

五条规则（先搬家后拆包，100% rename 证据是本阶段的验收）：

1. **顺序仍由清单独占**，目录布局纯粹用于导航；写进清单头部注释。
2. **路径允许子目录，装配协议不变**：edit.py 与 Tauri `build.rs` 各自把清单条目
   拼成路径，仍注入同一个脚本 token。
3. **路径只能向下**：拒绝 `..` 与绝对路径逃逸。
4. **分层按"谁允许读谁"命名**：顶层 `shared/`（无 DOM、双端共用）、`editor/`、
   `server/`、`boot/`；editor 内按域分（lib/state/ui/cues/timeline/playback/
   input/appearance/split/gap/stickers/text/export/project/onboarding/i18n/waveform）。
5. **契约测试断言装配结果，不断言单文件路径**——模块日后继续拆细不会让测试失效。

配套新增清单级全量语法测试（每条目逐个编译），搬家过程中任何文件被截断都会
在这里失败。

## 6. 阶段三：巨型 IIFE 拆解

### 6.1 什么算"过大"

行数只是提示。判定条件：文件顶层只有一个 IIFE 表达式（整文件一个闭包），且
闭包 ≥ 约 800 行。低于阈值不动——不能为了达到数字制造碎片化文件。

### 6.2 标准模式：namespace + 内部发布 + compat-surface

- `namespace.js` 是内部命名空间（`window.MaweXxx`）的**唯一所有者**，重复初始化
  直接抛错——顺序错误在加载期炸，而不是静默容忍。
- 各模块 `Object.assign(U, { … })` 发布符号；**可变状态必须用 `defineProperty`
  发布访问器**，值快照会把"每次重算"的语义变成"永远是第一次的值"——这是
  实际踩过的最险的坑。
- `compat-surface.js` 排在块尾，把历史出口（如 `window.AsrEditorUtils`）**按原文
  逐键重建**。键名与键序保持原样是后续"源码逐字节一致"差分的前提。
- 两条硬顺序约束写进清单头部并由契约测试守住：`namespace.js` 必须块首，
  `compat-surface.js` 必须块末。

### 6.3 四个特殊形态

- **类**（waveform 的 3960 行 `WaveformEditor`）：构造器留在 `core.js`（类唯一
  声明处），其余成员按职责搬进**原型混入**模块，加载期用描述符逐个复制
  （`Reflect.ownKeys` + `getOwnPropertyDescriptor`）。**不能用 `Object.assign`**——
  它会把 `get durationMs()` 这类访问器求值后降级成数据属性。
- **冻结门面**（split/core 的 `Object.freeze` 门面）：freeze 不妨碍访问器写入，
  compat-surface 按原文字面量逐字节重建即可，键序与访问器对保持原样。
- **未冻结的历史出口**（i18n 的 `MAWE_I18N`，5 个键是历史契约）：出口不冻结、
  内部命名空间另装词典等内部符号，内外两个面不相等，契约只能单向断言。
- **导出之后的顶层语句**（i18n 的 `start()` 启动分支）：改写器要有 `tail` 通道
  把导出之后的语句**原样**重新发射到出口赋值之后——`start()` 必须在新语言生效
  之后运行，提前执行等于改初始化语义。

### 6.4 门面 setter 的硬性不变量

如果**原始门面**里某个键是 `get/set` 成对的（外部经门面写入），owner 模块必须
发布 get/set 对——**不能**以"现在没人写"为由只发 getter：改写器看不见块外经
门面的写入，差分与单元测试也放不过它，只有真实浏览器点到才抛 TypeError。
取"原门面有 setter ⇒ 必发布访问器对"这个不依赖漂移事实的条件。

### 6.5 验证：三层差分，而不是"看起来一样"

把旧实现与新块分别装进两个 `vm` 上下文：

| 层次 | 比什么 |
| --- | --- |
| 结构 | 出口/命名空间的键名、键序、属性种类、frozen、值指纹（函数源码、原始值、嵌套键集合） |
| 源码 | 每个声明剥掉 `U.` 前缀后与原文件对应区间**逐字节**比对（简写属性先折叠 `x: x` → `x`） |
| 行为 | 对可调用导出发起成百上千次调用（含边界输入），逐项比对返回值与抛错；有共享状态时每次调用后比对状态视图 |

纯引用表（如 MaweDom 的 295 个键）没有函数可调：假 `getElementById` 返回带 id
的假元素，逐键比对取值指纹；写入探针**逐个全探**所有 setter。差分判据要被
反证过才算数（故意注入一处跨模块改写，源码层与行为层必须同时报差异）。

落盘文件与通过差分的 dryrun 产物 sha256 逐一相同，差分结论才适用于提交内容。
差分工具改过公共部分之后，已完成的块要复跑。

### 6.6 boot 接线：连续切段

平铺接线（数百条顶层语句，模块间只经命名空间对象联系）不能套上面的模式。
装配链的性质本身就是证明：清单顺序拼接 ⇒ "按行连续切段 + 顺序不变 ⇒ 拼回
脚本逐字节不变"。三个自证判据：

1. AST 逐条断言顶层语句无一被切断，各段无缝覆盖全文件；
2. 去掉每段新增头注释后按顺序拼回，与原文件逐字节相同；
3. 从真实清单复刻装配拼接，与原文件逐语句 AST 相同（判据曾被故意注入的
   错误切段命中，证明不是摆设）。

**段间顺序即注册顺序**：同一目标上的监听器按注册先后分发，"把小段并进邻居"
"把启动收尾挪到块尾"这类看似更合理的整理都会改变语义，必须挡住。

### 6.7 别忘了第二个注入方

任何被页面脚本以外的方式读入的块（如对齐页在 `serve.py` 里按文件路径注入
gap-remove 核心），拆块后注入源必须从"单文件路径"改成"按清单前缀拼接"
（`read_editor_scripts_under(area)`），并加占位符唯一性校验——宁可炸也不静默
注入半截。Node/Python 都不加载对齐页，这类破坏只有浏览器能看到。

## 8. 已知遗留

- 16 个预存 e2e 失败（见上）——它们反映的是真实的产品/测试问题
  （陈旧 spec 选择器、用例间共享工程文件撞上 400ms 防抖自动保存等），
  修它们属于另一件事。
- 两处逐字节相同的跨层重复实现（cloneJsonValue/clampInteger）按 Phase 3 决策。
- Tauri 侧只有 Rust 语法与共享清单契约证据，未本机跑 cargo。
- 便携 HTML 的真实双击打开路径未被 Playwright 覆盖。

按顺序执行，每步的详细方法在上面对应章节：

- [ ] jsconfig checkJs；依赖图分析产出簇划分（§4.2）
- [ ] 阶段一：按簇 codemod 迁移 editor.js，每批验证组合 + 提交（§4）
